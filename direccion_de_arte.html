Especificación de Celdas y Pesos en la IA

Tile Símbolo Costo Transitable Efecto en el Pathfinding (Dijkstra vs BFS)
Piso (Floor) . 1 Sí Ruta óptima estándar. Todos los algoritmos avanzan con igual prioridad.
Barro (Mud) ~ 5 Sí Clave Pedagógica: BFS lo atraviesa sin dudar. Dijkstra/A* calculan costo 5 y prefieren rodearlo por Piso aunque tome más pasos.
Agua (Water) w 8 Sí Terreno de altísimo costo. Sirve para forzar desvíos extremos en A*.
Muro (Wall) # ∞ No Bloqueo absoluto. Excluido del método neighbors() en Grid.

class TileSet:
    def __init__(self, sheet_path: str):
        sheet = pygame.image.load(sheet_path).convert_alpha()
        self.tiles = {
            ".": sheet.subsurface(pygame.Rect(0, 0, 32, 32)),   # Piso
            "~": sheet.subsurface(pygame.Rect(32, 0, 32, 32)),  # Barro
            "w": sheet.subsurface(pygame.Rect(0, 32, 32, 32)),  # Agua
            "#": sheet.subsurface(pygame.Rect(32, 32, 32, 32)), # Muro
        }

Reglas de Animación e Interpolación Visual:

  • El pathfinding opera exclusivamente sobre la coordenada lógica cell: tuple[int, int].
  • El renderer interpola la posición flotante visual: tuple[float, float] desde la celda de origen hacia la celda de destino durante move_duration (ej: 0.15s).
  • La animación incrementa el frame frame_index = (frame_index + speed * dt) % 4 únicamente mientras el personaje esté en transición visual entre celdas. Al estar quieto, se muestra el frame 0 (standstill).
game/entities/player.py - Carga de Sprites Python 3.11+ 
def load_player_sprites(sheet_surface: pygame.Surface) -> dict[str, list[pygame.Surface]]:
    dirs = ["down", "up", "left", "right"]
    sprites = {}
    for row, d in enumerate(dirs):
        sprites[d] = [
            sheet_surface.subsurface(pygame.Rect(col * 32, row * 32, 32, 32))
            for col in range(4)
        ]
    return sprites

Comportamiento del Agente & Reglas de Desempeño

Inyección de Pathfinder: La clase Guard recibe un objeto que cumple la interfaz Pathfinder (BFS, Dijkstra o A*). No conoce el algoritmo concreto.
Frecuencia de Recálculo: La ruta se recalcula únicamente cuando el jugador cambia de celda lógica, NUNCA en cada frame visual (evita caídas brutales de FPS y preserva la estabilidad del árbol de búsqueda).
Almacenamiento de Debug: El guardia guarda la última estructura SearchResult enviada por la IA para permitir al debug_overlay.py dibujar la frontera y los nodos visitados en la pantalla.
game/entities/guard.py - Actualización de Guardia Python 3.11+ 
class Guard(Entity):
    def __init__(self, cell: Coord, pathfinder: Pathfinder):
        super().__init__(cell)
        self.pathfinder = pathfinder
        self.last_search_result: SearchResult | None = None

    def on_player_moved(self, grid: Grid, player_cell: Coord):
        # Recalcula ruta solo al cambiar la celda del jugador
        self.last_search_result = self.pathfinder.find_path(grid, self.cell, player_cell)
        self.current_path = self.last_search_result.path

Directrices de Diseño del Overlay (Tecla TAB)

1. Transparencia Alphablend (SRCALPHA) Para dibujar los rectángulos semitransparentes de la frontera y visitados sin ocultar los sprites del terreno subyacente, instanciar un Surface((32, 32), pygame.SRCALPHA) y llamar fill((r, g, b, alpha)).
2. Números de Costo Acumulado (cost_so_far) Renderizar el valor numérico en la esquina superior izquierda de cada celda con una fuente monoespaciada de tamaño pequeño (ej: JetBrains Mono de 10pt) en color blanco brillante.
3. Flechas de Punteros de Inversión (came_from) Dibujar una flecha o vector corto apuntando desde el nodo hijo hacia el nodo padre de donde proviene la búsqueda.
